# AI 编导爆款拆解

目标不是复述内容，而是把公开样本转成一条可验证的决策链：

`传播假设 → 内容证据 → 编导决策 → 可执行改编 → 发布验证`

最终交付固定六部分：

1. 传播诊断
2. 画面、口播与留存时间轴
3. 主张—证据与风险
4. 可复用创作公式
5. AI 编导生产说明书与改编方案
6. 单变量测试与复盘计划

## 工作流

1. **自检**：运行 `bash scripts/check-deps.sh`。必需依赖失败时，先按输出补环境；TikHub、Jina 等可选项不阻塞本地 API 能覆盖的平台。
2. **识别**：判断平台与粒度。账号链接先抓 5–15 条，单条链接直接进入证据采集。取数和回退规则见 [references/fetch-playbook.md](references/fetch-playbook.md)。
3. **准备证据包**：运行 `bash scripts/prepare-assets.sh "<url>" [output_dir]`，随后读取 `manifest.txt`。
4. **短视频证据门槛**：必须同时具备元数据、完整口播转写、视频帧/contact sheet，并实际读图。缺一项只能给“初筛/部分拆解”，明确缺口，不冒充完整编导拆解。
5. **传播分析**：读取 [references/director-framework.md](references/director-framework.md)。区分传播目标、观众状态、核心承诺、钩子、留存、情绪、证据、CTA 和可复用边界。
6. **视觉与表演分析**：短视频读取 [references/visual-framework.md](references/visual-framework.md)，分析画面承担的内容功能、口播表演和剪辑/信息/叙事三种节奏。
7. **输出与存档**：使用 [references/output-template.md](references/output-template.md)，保存到 `benchmarks/<平台>-<账号>/<日期>-<标题slug>.md`；账号报告存为 `_account-<日期>.md`。

## 判断规则

- **事实**：能由元数据、原文、口播、画面或公开数据直接确认。
- **传播假设**：对“为什么有效”的解释，必须指出支持证据和可能的相反解释。
- **编导判断**：基于当前账号目标做出的取舍，不伪装成平台算法事实。
- **待验证项**：只能通过发布后的留存、互动或转化数据验证。

单条爆款不能证明平台算法偏好，相关结论只能表述为内容规律或待验证假设。新发布、互动不足或仅靠大号基础盘的视频，不自动称为爆款。

## AI 编导适配要求

- 明确视频主要换取播放、完播、收藏、分享、评论、涨粉还是转化；不要把所有指标混成“爆”。
- 目标观众写到任务和认知阶段，不使用“AI 用户”“普通人”这类过宽标签。
- 钩子拆成首帧、首句、未闭合问题、首次兑现时间。
- 时间轴每段标注内容功能、情绪变化、证据类型、留存机制和流失风险。
- 建立主张—证据表；作者口头宣称不等于已完成实测。
- 区分剪辑节奏、信息节奏和叙事节奏。快剪不等于留存好。
- 画面分析优先说明“抓停、证明、解释、降负担、建立信任、装饰”等功能，再补景别和运镜。
- 改编时明确可直接复用、需重做、不可复用三类内容，避免复制原句、人设、版权素材和未经核验的数据。
- 有当前账号定位、受众和生产条件时，给可拍的改编骨架、素材清单和表演/剪辑指令；没有这些上下文时，只给条件化方案并列出所需信息，不虚构“适合你的成稿”。
- 测试计划一次只改变一个主要变量，并写清观察指标和停止/升级条件。

## 账号级要求

先比较同账号的普通样本与高传播样本，控制粉丝量、发布时间和内容类型的差异，再提炼重复规律。挑 1–2 条代表作进入完整六部分拆解；不能从一个孤立爆款推导稳定账号公式。

## 硬性边界

- 取不到内容时按回退链继续；最终仍失败则请用户粘贴文案、字幕或截图，不空手报错。
- 敏感凭证、Cookie、Token、Webhook、个人隐私不进入报告或 Git。
- 完整短视频报告末尾附 Whisper 原始转写，并标注可识别的同音词错误；不得把错词改写成技术事实。
- 输出是编导分析与生产建议，不自动制作、发布、评论、私信或改变外部账号状态。
